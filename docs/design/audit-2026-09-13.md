# Audit of the simulator at commit c304d94 (main, 2026-09-13)

Scope: App.tsx state management, simulation/pure.ts, the Futures tab, the validation runners, and
the labels the site shows. Method: reading the code plus small scripts run against the engine.
Each finding below was reproduced, not inferred. Severity is about what a user is told.

## Findings

| # | Severity | Finding | Evidence | Fix (stage 1) |
|---|---|---|---|---|
| A1 | **Critical** | The engine mutates country objects in place. `stepSimulationPure` shallow-copies the country map and then writes wellbeing, adoption, UBI fields and the trend array on the shared objects, so every stored history point silently becomes the latest month. | Script: after six steps, month-1's recorded US wellbeing 65.2 reads back as 32.2; `history[1].state.countryData.USA === history[6]...` is `true`. Charts hid it because `averageWellbeing` is a scalar copied per step. | Clone every country (and shadow) at the start of a step. Done in `simulation/pure.ts`; test in `simulation/run.test.ts`. |
| A2 | **Critical** | The same mutation reached the `INITIAL_COUNTRIES` constant: its `wellbeingTrend` array was shared with the first state and grew across runs, so anchor tests were order-dependent. | `INITIAL_COUNTRIES[USA].wellbeingTrend.length` goes 1 → 6 after one anchor suite on the old engine. On a clean engine AT-3 fails; the published "5 of 6" was an artefact. | Baseline re-locked at 4 of 6 with the reason in `validation/anchorTests.test.ts`. README and the Models tab wording must say so. |
| A3 | **High** | Seek restores countries from history but not corporations, ledger or game-theory state, so a seek mixes the past with the present. | `handleSeek` sets `state` only; `HistoryPoint` is `{month, state}`. | History points carry the whole `SimulationRun` (`simulation/run.ts`); seek restores all four, or replays when a save is old. |
| A4 | **High** | Comparison mode never advances. The comparison panel shows month 0 forever while the main panel plays. | Play loop comment: "comparison state is set once and shows static snapshot at month 0"; `setComparisonState` is only called on reset. | Both runs advance in lockstep from one `SimulationRun` each; the zero-policy-difference invariant is a test. |
| A5 | **High** | An uploaded model whose equations fail to compile silently runs the built-in engine while the custom model stays selected and labelled. | `stepSimulation`: "null/invalid falls back to the default hardcoded engine". | Compilation returns structured errors; the app refuses to step and shows them; no fallback under the custom label. |
| A6 | Medium | Save files and autosave store countries, corporations, ledger and game theory but rebuild shadow data from the main data on load, and history points inside them suffer A1. | `handleLoad`, autosave effect. | Save the run; on load, validate and replay if history is partial. |
| A7 | Medium | Side effects inside a React state updater: `setState(prev => { setCorporations(...); setGlobalLedger(...); ... })`. Works in production, double-fires in StrictMode, and is why the four pieces of state drift. | `stepSimulation`. | One `run` state object advanced by `advanceRun`. |
| B1 | Medium | The Korinek macro block's `reemploymentMonths` is sourced to "extreme scenario mu = 0.04/month"; in the paper mu is a dimensionless search discount, not a monthly hazard. The block is a reduced-form approximation calibrated to their outputs, not their mechanism. | `constants.ts` DEFAULT_MACRO / KORINEK_SCENARIOS source strings; README reproduction table. | Relabel as "reduced-form approximation calibrated to Korinek et al. 2026 published outputs"; keep the tests, rename the claim. |
| B2 | Medium | Futures cost curve ranks interventions by mean shift divided by an ordinal cost band (1 to 5). A ratio of a quantity to an ordinal is not a cost-effectiveness number. | `src/futures/interventions.ts` `shiftPerCost`; InterventionPanel table. | Sort by mean shift; show the band as a band; drop the ratio column. |
| B3 | Medium | The "Flow between world-states" Sankey is built by a minimal-movement rule, not simulated transitions, but is not labelled as such. | `engine.ts stateFlows` doc comment vs the panel caption. | Caption: "constructed from the marginals by a minimal-movement rule; not a simulated transition". |
| B4 | Medium | The hindcast wellbeing anchor was fitted on the same 2015 to 2025 data it is scored on; the score is a reconstruction, not a forecast. | `wellbeingAnchor` comment; README hindcast paragraph. | Label it calibration; add a persistence baseline to the report. |
| B5 | Low | "Tier-2 eligible (4 of 6)" reads as scientific validity; it is a leaderboard admission rule. | `validation/testRunner.ts`, Models tab. | Rename to "leaderboard eligible" in the UI and README. |
| C1 | Low (known) | Under the default preset, US wellbeing collapses to 1 within 12 months and the regional branch then drains the global fund. | Diagnosed 2026-09-10. | Out of stage 1 scope; belongs to qualifying the default (v3 stage 3). |
| C2 | Low (known) | Corporation-driven adoption saturates the US within months. | Diagnosed 2026-09-10. | Same as C1. |

## Stage 3 addendum (same day): qualifying the default

Traced with `scripts/response-profile.ts` and two scratch scripts against the engine at 6579ba7.
Full disclosure lives in `docs/design/model-card-default.md`; this table records what was found
and what was decided.

| # | Severity | Finding | Evidence | Decision |
|---|---|---|---|---|
| C2 | **High** (re-rated) | Country AI adoption was incremented once per corporation operating there, so it scaled with the number of rows in the corporation table. 74 corporations serve the US: adoption went 0.01 to 0.54 in month 1 and 0.90 by month 3. | Trace at 6579ba7: US adoption 0.541 at month 1. | **Artefact, fixed.** One logistic step per country per month from the mean `aiAdoptionLevel` of the corporations serving it. US adoption now 0.13 at 1 y, 0.47 at 5 y, 0.72 at 10 y. Shadow path aligned (half speed, same form). |
| C3 | **High** | Per-capita monthly UBI was computed as `totalUbiAmount / (population x 10)` with amounts in billions and population in millions; the correct conversion is `x 1000 / population`. Per-capita UBI was understated 10,000-fold, so no contribution rate could move wellbeing, which is why AT-2 failed. | Trace: 40% global contribution gave "US UBI 0.018 USD/month" against 3,934 USD/month of lost wages. | **Artefact, fixed.** AT-2 now passes (ratio 1.065). |
| C4 | Medium | AI revenue used `adoption x marketCap x 0.15` per month; 15% is an annual revenue-to-market-cap ratio. Revenue was overstated twelvefold (3,150 bn USD/month across 79 corporations, more than their combined market cap per year). | Trace at 6579ba7. | **Artefact, fixed** (`/ 12`). Assumed ratio, not estimated; disclosed in the card. |
| C1 | Medium (re-rated) | The US collapse was C2 + C3 + the crisis rule. With C2-C4 fixed, US wellbeing holds ~92 for four years, then falls to 57 at 5 y and 1 at 10 y as adoption passes ~0.4, where lost wages (adoption x 0.75 x wage) exceed 30% of the wage and the crisis penalty (up to -5/month, uncapped in time) applies every month. | `profile:default` base rows. | **Rule, disclosed.** The crisis rule is a modelled regime switch and is listed as a threshold in the card. Whether 75% of labour income vanishes at full adoption with no re-employment is the model's central assumption; it is not evidence-backed and is marked so. Changing it is a stage-4 decision. |
| C5 | **High** (new) | With real per-capita units the UBI-to-wellbeing coefficient is far too strong for poor countries: switching every corporation to global distribution (~16 USD/person/month) raises the poor-8 mean wellbeing by +58 points at 10 y. The coefficient was tuned while UBI was effectively zero and was never exercised. The hindcast shows the same: "AI off, UBI on" fell from r 0.485 to 0.181. | `profile:default` switches table; `npm run hindcast`. | **Open, disclosed.** Recalibration needs transfer-size evidence (cash-transfer literature) and belongs to stage 4. Until then the card marks every UBI-driven wellbeing gain as illustrative. |
| C6 | Medium (new) | Five parameters shown in the configuration panel are never read by the engine: `corporateTaxRate`, `adoptionIncentive`, `globalRedistributionRate`, `marketPressure`, `defaultCorpPolicy` (the last shapes preset corporation tables only). Sliders that do nothing. | `grep "model\." simulation/pure.ts` reads only `aiGrowthRate`, `displacementRate`, `gdpScaling`, `macro`. | **Disclosed** in the card and labelled in the panel; removal is a UI decision for the owner. |
| C7 | Low (new) | The corporate contribution rate is not an effective lever beyond ~3 years: the demand-collapse trigger raises every corporation's rate by 0.02/month whenever customer wellbeing falls below 40, so all starting rates converge. +/-10% on the starting rate moves 10-year average wellbeing by 0.0. | `profile:default` nudges table. | **Rule, disclosed.** |
| H1 | Medium (harness) | The hindcast "AI off" run set contribution rates to 0 once, but the same trigger raised them during the run, so the AI-off score included UBI. Invisible while C3 hid UBI; with real units it moved r from 0.485 to 0.143. | `npm run hindcast` before/after. | **Fixed:** the harness pins the configured rate every month. AI-off score back to r 0.485, MAE 4.48. |

Baseline after stage 3: anchor 5/6 (AT-3 fails), Korinek 3/3, hindcast AI-off r 0.485 / MAE 4.48 index points (persistence baseline MAE 4.68), 471 vitest tests.

## What is not wrong

- The engine is deterministic and the compiled-equation path reproduces the hardcoded path exactly (golden test).
- Money conservation holds (AT-6).
- The Futures engine reproduces its seeds exactly and its state marginals sum to one at every year (154 tests).
- The Korinek numbers are reproduced within tolerance; only the label of the mechanism was wrong.
