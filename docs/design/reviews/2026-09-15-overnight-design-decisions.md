# Overnight design decisions, 15 September 2026

These decisions explain the implementation scope for the owner and the next Claude Code task. Integration and UI comparison status are recorded separately; this document does not claim a deployment.

1. **Use existing authorization.** Proceed with the approved v3 review fixes and GitHub release without requesting the same permission again. Changing the scientific scope silently would cost trust; the narrower scope is recorded below.
2. **Keep the world product.** Do not replace it with a training or US-only model to manufacture default acceptance. Generic models remain in Model Lab. The cost is maintaining explicit capability boundaries between the world, generic equations and separate risk model.
3. **Apply execution limits to direct callers too.** Extend worker limits to direct paired execution so the same job cannot bypass the budget through another entry point. The cost is compatibility work for downstream policy/replay callers.
4. **Separate optional redesign from release repairs.** The initial core work proceeded without a homepage redesign when no optional UX answer had arrived. The owner's subsequent overnight authorization added an isolated interface branch and comparison. Its cost is carrying final core changes into that branch before comparison.
5. **Qualify conditional accounting only.** The default's modeled source is fully available by definition unless an explicit assumed available-share is changed. No invented cash margin or behavioral saturation is treated as evidence. Resource/allocation accounting is independently checked; macro and wellbeing are illustrative. This uses v3 section 4's narrower-scope option. The cost is that this release cannot claim to identify the empirically best policy or forecast wellbeing.
6. **Preserve progress in a draft PR.** Publish reviewed checkpoints on PR17 while remaining work continues. Draft checkpoints are not stage completion, merge or deployment. The cost is keeping PR descriptions and final CI tied to the actual reviewed head.
7. **Isolate conditional execution.** A bounded conditional helper selected by one execution discriminator shares appropriate macro primitives and preserves legacy execution. Its cost is one additional module; it avoids pretending legacy feedback exists in the conditional default.
8. **Share actual scenario inputs.** Expand world links to preserve corporate contribution/allocation edits and current snapshots; route generic equation and Futures payloads to their true owners, with explicit failure for malformed input. The cost is large world links and imported-history status. Numerical reopening is not evidence that every email/chat channel can deliver such a link. Complete file export is available.
9. **Merge the functional PR; retain the UI comparison.** Existing owner authorization covers pushing and merging the verified core changes. The overnight interface experiment stays unmerged for comparison. Worktrees are retained for previews/handoff; no destructive cleanup or cloud deployment is part of this plan.
10. **Use independent work without concurrent implementation.** Start UI implementation from the checked core at 08c28a6 while the final core reviewer works read-only. Only one implementation agent runs at a time. Any final core fixes must be carried forward before the matched comparison. The cost is a small integration/review step, not a weaker release gate.
