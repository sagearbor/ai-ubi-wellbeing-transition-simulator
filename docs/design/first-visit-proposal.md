# First-visit proposal — 15 September 2026

Status: proposal, not shipped. Based on inspection of the public app on 15 September. The current release work repairs model and policy integrity; a full homepage redesign is a separate optional expansion.

## Product promise

Explore how AI gains could be distributed, see which constraints matter, and inspect the assumptions behind the result. A visitor should make one useful comparison before learning the model taxonomy.

## First minute

1. Arrive at a single question: **Where could the gains from AI go?** Offer **Explore a dividend**, **Try a policy idea**, and **Open the Model Lab**. Explain each in one sentence. The Lab remains directly visible to returning authors.
2. Open a useful, precomputed default comparison with its scenario name and scope visible. Show at most three pertinent outputs: available funding, receipts per person, and the model-implied wellbeing difference where supported. Unsupported outcomes say why they are unavailable.
3. Change contribution or allocation using a few controls beside the comparison. Place economic response assumptions in an expandable panel labeled **Assumptions**, separate from policy choices.
4. Explain the result directly below it: where funds come from, where they go, which constraint binds, and which effects the model does not estimate. A computed plateau needs a concrete reason; a display bound is not a policy constraint.
5. Offer **Compare another approach**, **Inspect equations**, and **Share this scenario** next to the result. Reopening a share should restore the same model, assumptions, source text and status.

## Navigation and layout

Use three primary destinations: **Explore**, **Compare**, **Model Lab**. Keep the model card, data sources and methods in contextual links and a compact About menu. Map and chart are views of the selected result, not separate simulations whose identity the visitor must remember. Corporation details belong to compatible world scenarios. Futures remains a clearly separate model until an explicit supported bridge exists.

Desktop: question and three output cards at the top; a compact control panel beside one comparison chart; an expandable explanation below. Mobile: question, outputs, controls, chart, explanation. Do not make the initial screen a matrix of eleven metrics and many competing presets. Always keep the selected scenario and evidence status visible.

The policy route should read: **Paste → Inspect → Run → Explain → Share**. Inspect must show every operative clause as mapped, unresolved or outside the model. AI extraction proposes a mapping; the interface must never disguise an unmapped tax or eligibility rule as a measured zero effect. Provide a worked example for visitors without their own text.

## Preserve depth

The simplified entry point must retain model import, equation authoring, new variables and effects, published references, parameter uncertainty and reproducible downloads. Progressive disclosure changes the order in which people encounter these capabilities; it does not remove them. Every advanced route should offer an example and a clear return to the active result.

## Acceptance checks for a later interface release

Ask a first-time visitor to explain the selected question, change a contribution, identify a binding constraint, find one assumption, and reopen a shared result. Observe failures directly. Success is task completion and correct interpretation, not only an attractive screenshot or fewer clicks. Verify narrow screens, keyboard navigation, cancellation, unsupported views and error recovery.
